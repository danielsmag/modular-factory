Install

Install mfactory once for your user, then install the factory into each repository. Setup fills in factory.toml. Doctor checks that a run can start.

What you need

  • A git repository with a GitHub remote named origin.
  • Python 3.11 or later as python3.
  • git, and the GitHub CLI gh, signed in (gh auth login) with write access to the repository.
  • One of Claude Code, Cursor, or Codex.

The factory adds nothing to your project's dependencies. It is a folder of Python files that use only the standard library. macOS, Linux, or WSL. The script uses fcntl and bash.

Install the command

curl -fsSL https://raw.githubusercontent.com/danielsmag/modular-factory/master/install.sh | bash -s -- --global
OptionMeaning
--globalInstall mfactory for your user. Do not combine it with --tool.
--version v0.2.0Install that release. Default: the latest release, or the master branch before the first release.
--source DIRInstall from a local copy of this repository instead of downloading.

This creates ~/.mfactory (FACTORY_HOME when set) and links ~/.local/bin/mfactory. It also serves the dashboard. The workspace, the list of your projects, is ~/.mfactory/workspace.toml.

To read the script before running it, download it first:

curl -fsSL -o install.sh https://raw.githubusercontent.com/danielsmag/modular-factory/master/install.sh
less install.sh
bash install.sh --global

Install into a repository

From the repository:

mfactory install --tool claude

To install straight into the repository you are in, without a command on PATH:

curl -fsSL https://raw.githubusercontent.com/danielsmag/modular-factory/master/install.sh | bash -s -- --tool claude
OptionMeaning
--tool claude|cursor|codexThe tool to generate agents for. Repeat it, or separate names with commas. Default: claude.
--personalKeep factory.toml, .factory/ and the generated files untracked in this checkout. Writes .git/info/exclude and does not touch .gitignore.
--version v0.2.0Install that release.
--source DIRInstall from a local copy instead of downloading.

The installer prints each step. The version numbers below are an example:

ok    .factory/ installed (version 0.2.0)
ok    factory.toml written
ok    .gitignore gained /.factory/jobs/, /.worktrees/
ok    generated files for claude
ok    GitHub labels: factory, factory:needs-info, factory:needs-human
PathWhat it isCommit it?
factory.tomlYour configuration. The only file you edit.Yes
.factory/The factory: its CLI, prompts, and defaults.Yes
.factory/jobs/The state and files of each job.No, ignored
.worktrees/One git worktree per running job.No, ignored
.claude/agents/mfactory-*.mdOne small agent file per step, generated from factory.toml. Cursor and Codex use their own folders.Yes
.claude/skills/mfactory/The /mfactory skill. Codex uses .agents/skills/mfactory/.Yes

Running the installer again is safe: it never overwrites factory.toml.

Personal install

Use this when the factory is for you, not for everyone who clones the repository. .gitignore stays as it was.

mfactory install --tool claude --personal

The same flag works from the installer script and from the Makefile:

curl -fsSL https://raw.githubusercontent.com/danielsmag/modular-factory/master/install.sh | bash -s -- --tool claude --personal
make install PERSONAL=1 TOOL=claude

The installer appends this block to .git/info/exclude. The patterns cover every tool, so turning one on later does not show new files in git status:

Next:
  1. In your tool, run `/mfactory setup` to fill in factory.toml (or edit it yourself).
  2. Run `.factory/bin/mfactory doctor`.
  3. Leave factory.toml, .factory/ and the generated files untracked. This checkout ignores them.
  4. Label an issue `factory` and run `/mfactory run`.

git status does not list factory.toml, .factory/, or .claude/agents/mfactory-build.md. git check-ignore -v factory.toml names .git/info/exclude.

Running mfactory install again in that checkout, without --personal, does not touch .gitignore:

ok    .git/info/exclude already ignores the factory (personal install)

doctor then reports:

ok    factory.toml and .factory/ are ignored in this checkout (.git/info/exclude). Worktrees built from origin/main do not contain them. A check that needs those files must use the main checkout.

Jobs build a worktree from origin/<base>. That worktree does not contain factory.toml or .factory/. A check command that needs those files has to reach the main checkout itself. Skip the commit step below.

To install for the team afterwards, delete that block from .git/info/exclude, then run mfactory install. That run appends /.factory/jobs/ and /.worktrees/ to .gitignore and tells you to commit.

mfactory upgrade in a personal checkout ends with:

Next: run `.factory/bin/mfactory doctor`. Leave factory.toml, .factory/ and the generated files untracked.

Set up

In your coding tool, in the repository:

/mfactory setup

In Codex, mention the skill with $factory setup, or ask in words: "set up the factory".

The agent reads your README, package manifest, and CI workflows, then edits factory.toml:

  • [project] description: what the project is for. Intake judges issues against this.
  • [checks] commands: the commands that install dependencies and run lint, tests, and the build. These decide whether a build may be reviewed.
  • [skills]: which of your project's skills agents read.

It asks before turning on any optional step. By default a maintainer merges the pull request and the factory does not. Ask whether a merge to the base branch publishes a release. Only when it does not, and you want the factory to merge, turn the merge step on. See who merges. You can also edit factory.toml by hand. The reference lists every key.

After any change to factory.toml:

.factory/bin/mfactory sync

This rewrites the generated agent files to match.

Commit

git add factory.toml .factory .gitignore .claude .cursor .codex .agents 2>/dev/null
git commit -m "Add the software factory"
git push

Then run a job.

More than one tool

[tools]
enabled = ["claude", "cursor"]

mfactory sync writes agent files for each. Any one of the tools can run /mfactory run. They share the same job state in .factory/jobs/, so do not run two orchestrators on the same checkout at the same time.

Cursor also reads .claude/skills. With Claude Code and Cursor enabled, the factory writes the skill only to .claude/skills/mfactory, so Cursor lists it once. With all three tools enabled it also writes .agents/skills/mfactory for Codex, and Cursor may list the skill twice. The copies are identical. See Tools.

Upgrade

mfactory upgrade
mfactory upgrade --version v0.2.0
mfactory upgrade --self
mfactory upgrade --all

mfactory upgrade updates the CLI from install.sh --global and every project in the workspace. Standing in an installed checkout that is not listed updates that checkout too. It replaces .factory/ (not .factory/jobs/), runs sync, and leaves factory.toml alone. It refuses a release whose schema number differs from your factory.toml. The changelog says what to change when that number moves. One project failing does not stop the others. Commit the result in each repository. A personal install stays untracked: upgrade tells you to leave factory.toml, .factory/ and the generated files untracked.

--self updates only the global CLI. --all upgrades only the projects in the workspace.

Remove

mfactory uninstall
mfactory uninstall --config
mfactory uninstall --labels

uninstall removes .factory/, the generated agent and skill files, the job worktrees, and the checkout from the workspace. factory.toml stays unless you pass --config. --labels deletes the three factory labels on GitHub. It needs factory.toml still readable, so pass --labels together with --config or before deleting the file yourself.
