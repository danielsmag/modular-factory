Claude Code, Cursor, and Codex run the same prompts. A generated agent file holds only that tool's settings, a pointer to the role, and the sections that come from factory.toml.

Enable the tools you use:

[tools]
enabled = ["claude", "cursor"]

mfactory sync rewrites the generated files. Edit factory/, never those files. mfactory sync --check exits 1 when anything is out of date and changes nothing.

The command is mfactory. Generated agents are mfactory-*. The skill command is /mfactory. A /factory comment on an issue or pull request still counts. mfactory sync removes generated files that still use the old names, so an upgrade from 0.1.0 can finish.

Intake

Intake is the step that reads an unreviewed issue, so each tool gives it as little as that tool allows. The full account is on Guards. The short version: Claude Code writes intake.md itself. Cursor and Codex hand the file's contents back as the agent's reply, and done --reply writes it.

On Codex, if an agent with shell_tool = false cannot read the project, set [tools.codex] intake_shell = true. That is a weaker guard.

Models and effort

Each tool has its own table, because model names differ. [models.<tool>].default applies to every agent of that tool that names no value of its own, so one line gives Cursor or Codex a model for every step.

[models.claude]
build = { model = "opus", effort = "high" }
reviewer-code = { model = "sonnet", effort = "medium", low = { model = "haiku", effort = "low" } }

[models.cursor]
default = { model = "gpt-5.6-sol", effort = "medium" }

low, medium, and high inside an entry are the job's risk, which intake decides. The factory writes one extra agent file per variant, such as mfactory-reviewer-code-low, and starts the right one. model = "inherit" uses the model of the session that runs /mfactory run.

Cursor takes an effort only together with a named model. mfactory sync says so when an effort would be ignored. The factory does not check model names: a name your tool does not know fails when the agent starts. Every key, the shipped defaults, and the effort levels each tool accepts are in factory.toml.

[tools.claude] stop_hook runs the checks when the build agent stops, and sends it back to work if they fail. Claude Code only. [tools.claude] resume_builder wakes the job's builder with SendMessage in later rounds instead of starting a new one, while the same session runs the job and the builder's model and effort are unchanged. [tools.claude] cost works out each job's cost from Claude Code's transcripts. Other tools record no cost. [tools.claude] plan_usage (on by default) records the Session and Weekly plan limits that /usage shows, through a status line in .claude/settings.local.json that runs your own status line after it. The dashboard then shows those limits and the plan usage of each step.

One skill, or two

A tool gets its own copy of the /mfactory skill only when no copy already sits in a folder it reads.

  • Claude Code and Cursor: the skill is written only to .claude/skills/mfactory. Cursor reads that folder, so it lists the skill once.
  • All three: Codex also gets .agents/skills/mfactory. Cursor may list the skill twice. The copies are identical.

Do not run two orchestrators on the same checkout at the same time. They share .factory/jobs/.
