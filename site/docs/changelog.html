Changelog

Versions follow semantic versioning. Until 1.0.0, a minor version may change factory.toml keys. The schema number changes when it does, and the changelog says what to change.

The repository copy is CHANGELOG.md.

0.2.1

  • A docs site at danielsmag.github.io/modular-factory/docs, in the dashboard's look. The dashboard's DOCS button opens it.

0.2.0

The factory no longer merges by default. After approval it marks the pull request ready and waits at ready-to-merge. A hand merge continues from the merge step's MERGED edge. Schema stays 1. A project that never overrode approve or merge changes behavior on upgrade. To keep the old behavior, point approve at merge, switch ready-to-merge off, and set [steps.merge] enabled = true.

  • A build that stops before it rewrites build.md can leave progress.md. The next builder of that step is told to read it. done deletes the file once the build outcome is accepted.
  • mfactory start dashboard serves the dashboard in the background. mfactory stop ends it. mfactory dashboard still stays in the foreground until Ctrl C.
  • The command is mfactory. Generated agents are mfactory-*, and the skill command is /mfactory. A /factory comment still counts. mfactory sync removes generated files that still use the old names.
  • install.sh --global installs mfactory for your user. mfactory install, upgrade, uninstall, doctor, status, and sync manage a project. mfactory upgrade --self updates that user install.
  • The fleet file is ~/.mfactory/fleet.toml. mfactory fleet subscribe adds a checkout. Outside a repository, mfactory dashboard and mfactory status show every subscribed project. mfactory upgrade --all upgrades each one.
  • One local queue and one read-only dashboard for several installed projects. Each job stays in its own checkout. [run].concurrency caps one project. [fleet].concurrency caps new and resume rows across projects. fleet.toml or --concurrency overrides the fleet cap.
  • One dashboard for every subscribed project. Board, pipeline, jobs, and config are the same page, with a filter for All or one project.

0.1.0

First version. schema = 1.

  • One factory.toml per project: pipeline, checks, models and efforts, reviewers, surfaces, project skills. It merges key by key over the defaults, and a mistake is reported with the key to fix.
  • The pipeline is a graph of steps with outcome edges. A max on an edge limits how often a step may send a job back.
  • Step types: agent, checks, review, human, merge, verify. A project adds its own agent and human steps in factory.toml.
  • Optional steps, shipped switched off: approval of the spec, a debugger after failing checks, and validation after merge or deploy.
  • Model and effort per step and per tool, with variants by the job's risk.
  • Adapters for Claude Code, Cursor, and Codex.
  • install.sh, init, upgrade, and doctor.
  • A read-only dashboard: board, pipeline, jobs, and configuration.

Known limits

  • No job has yet run inside Claude Code, Cursor, or Codex. See what is untested.
  • macOS, Linux, or WSL only.
