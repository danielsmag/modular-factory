First job

Label a GitHub issue factory. In your coding tool, run the factory. A job that needs a person stops and says so. Other jobs keep running.

Install and /mfactory setup come first. See Install. The first real run should be on a throwaway repository.

Label an issue

Only issues with the factory label run. Adding a label needs triage or write access, so the label decides whose issues the factory builds. mfactory install creates three labels:

  • factory — the queue.
  • factory:needs-info — the author is being asked something.
  • factory:needs-human — a maintainer is being asked something.

The names are keys. A /factory comment on an issue or pull request still counts. The command you type is /mfactory.

Run

/mfactory run                  work through every issue labeled factory
/mfactory run 12               run issue 12 now
/mfactory approve 12           answer a job that is waiting for you
/mfactory setup                fill in factory.toml, once after installing
/mfactory <anything else>      ask about jobs, or describe a feature to file as an issue

In Codex, mention the skill with $factory, or ask in words.

A job is named by its id (004-dark-mode), the number in that id (004), or its issue (12 or #12). Commands that take a job accept any of those.

What the orchestrator does

The orchestrator asks .factory/bin/mfactory what to do, starts the agents the script names, and reports back. It never writes code, specs, reviews, or decisions, and it never edits .factory/jobs/.

next prints one of these:

It printsWhat happens
start-agentStart that subagent, in the background, with the printed prompt unchanged.
parallelStart every named agent in one message so they run together. Reviewers do this.
thenWhen the agent has finished, run this command. Usually done.
stdinPipe the agent's whole reply to done --reply. Intake on Cursor and Codex works this way.
waitThe job is waiting for a person. Leave it.
holdNo free slot. Run next again after another job finishes.
finishedThe job is over: done, rejected, or failed.

After every done, the orchestrator runs next for that job again, until it prints wait, hold, or finished. A checks, merge, or verify step can run for a long time. Let it finish.

The agent name carries the model and effort from factory.toml. The orchestrator does not pick a model, and it does not paste issue text into a prompt. Issue text reaches agents only inside the job's issue.md.

Answer a person

A job that needs a person stops and says so on the issue or the pull request. You answer there with a comment, or in your tool. Nothing else waits: other jobs keep running.

/mfactory approve 12
/mfactory changes 12 Use the existing Money type instead of a new one.
/mfactory reject 12 Out of scope for this quarter.

On the issue or pull request, leave the number off:

/mfactory changes Use the existing Money type instead of a new one.

The word after /mfactory is the outcome's name in lower case. A step with on = { SHIP = "merge", HOLD = "build" } takes /mfactory ship and /mfactory hold. Words that come with the reply are saved, and the next agent is told to act on them. REJECT needs a reason. Who may reply depends on the step: the issue's author, someone with write access, the operator, or a named list of logins. replies = "tool" ignores comments. See human steps.

Merging the job's pull request by hand continues the job from the merge step's MERGED edge, including when that step is off. On the default path this does not sync the base branch or run the checks again.

Watch

.factory/bin/mfactory dashboard
mfactory start dashboard
mfactory stop

dashboard stays in the foreground until Ctrl C. start dashboard serves the same page and returns. stop ends that process. The page is read-only. Overview is the job table. Approvals and feedback go through /mfactory or an issue comment. See Workspace and dashboard.

Permissions

The orchestrator runs .factory/bin/mfactory. The agents it starts run git, gh, and your project's check commands inside the job's worktree. If your tool asks before each command, allow these for the repository, or a run stops at every step waiting for you.
