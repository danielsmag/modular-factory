Guards

What keeps a job from steering the pipeline, passing a failing build, or rewriting the agents that judge it. None of this removes the risk. It narrows it.

The label

Only issues with the factory label run. Adding a label needs triage or write access. That is the trust boundary: whose words the factory will build.

Issue text is data

Issue text reaches agents only inside issue.md, which every prompt calls quoted data. The orchestrator never pastes it into a prompt. This lowers the risk of an issue steering an agent. It does not remove it.

Limiting intake

Intake reads an issue nobody has reviewed. Each tool can limit what it may do.

  • In Claude Code, every agent, intake included, gets every tool by default ([tools.claude] agent_tools = ["all"]), so plugin and MCP tools work. To give intake only the read and write tools and no shell, set [steps.intake] tools = ["default"].
  • In Cursor, the only restriction an agent file offers is readonly, which also stops intake writing intake.md. Intake replies with the file's contents. The orchestrator passes the reply to mfactory done <job> --reply, which checks it and writes the file.
  • In Codex, intake's file sets shell_tool = false and hands in its reply the same way. Whether a Codex agent without a shell can still read the project's files has not been tried. If it cannot, set [tools.codex] intake_shell = true. Intake then has a shell on Codex, which is a weaker guard.

Checks are a script

No agent's opinion can pass a build whose checks fail. [checks].commands run in order in the job's worktree. The first command that exits non-zero fails the step. They run at the gate step, and again in the merge step after the base branch is merged in, when that step is on.

A command must not rewrite files. Use prettier --check, not prettier --write.

Protected paths

The checks fail any branch that touches factory.toml, .factory/, a generated agent or skill file, or a path in [paths].protected. A job cannot change the pipeline, the checks, or its own judges. This holds whatever the check commands say, and whatever protected lists.

* in a pattern also matches /. A job may add new files that match a protected pattern. It may not change or delete one that already exists.

Merge and replies

The factory merges only when the merge step is on. By default that step is off: a maintainer merges, and a hand merge continues from the merge step's MERGED edge. When the step is on, the script merges only after the base branch is merged in and the checks pass again. The factory never deploys and never merges a revert.

A reply to a human step counts only from the issue's author, from someone with write access, from the operator, or from named logins, depending on the step. replies = "tool" ignores comments and takes the reply from the coding tool. Comments from anyone else are ignored.

The dashboard

The dashboard changes nothing. It answers only on 127.0.0.1, refuses requests with another Host header, serves only .md and .log files from .factory/jobs/, and has no route that writes. Its page loads nothing from elsewhere and builds itself without ever turning text into markup, because job and issue text comes from GitHub and Jira. Agent activity sends the tool name and a short label only, not tool output, file contents, or assistant replies.

The Board's Jira and GitHub blocks are read by the server, only when the page asks, through a short cache and with each project's own settings. The Jira token stays in the server's environment: it never reaches the page, a file, or an error message.

What is untested

No real tool yet

The tests run whole jobs through the real script in temporary git repositories, with a stand-in for gh. They do not cover anything that needs a real tool or the real GitHub.

  • No job has run in Claude Code, Cursor, or Codex. The generated agent files follow each tool's documentation. No tool has loaded them.
  • Whether each tool's main agent follows the orchestrator skill: starts agents by the exact name, in parallel, in the background, and passes prompts unchanged.
  • Handing in intake's file as a reply, on Cursor and Codex.
  • Whether a Codex agent with shell_tool = false can read files.
  • Whether Cursor lists the /mfactory skill twice when all three tools are enabled.
  • Model names. The factory does not check them.
  • The real gh. The factory calls gh api, gh issue, gh pr, and gh label with the documented flags. Only the stand-in has answered.
  • install.sh downloading from GitHub. The tests install from a local copy.
  • Windows.
