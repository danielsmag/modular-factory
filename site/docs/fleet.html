Fleet and dashboard

The dashboard is a read-only page on your machine. A fleet is a list of checkouts that share that page and a second cap on how many jobs start.

Dashboard

mfactory dashboard
mfactory start dashboard
mfactory stop
mfactory dashboard --port 4747 --no-open

dashboard stays in the foreground until Ctrl C. start dashboard serves the same page and returns. stop ends that process. The default port is 4747.

The page has four views:

  • Board. Jobs by step, and a running total of merged jobs with a steady-pace line. With a few merges a week, a per-day chart is mostly zeros.
  • Pipeline. A column of steps. Forward edges on the right, back edges on the left, and how many jobs sit in each step.
  • Jobs. What each job wrote: spec, build, checks, reviews.
  • Config. The merged configuration, and which file set each value.

It changes nothing. Approvals and feedback go through /mfactory or an issue comment. It answers only on 127.0.0.1, refuses another Host, and serves only .md and .log files from the jobs folder. See why.

Inside a subscribed checkout, mfactory dashboard opens with that project selected. Outside a repository, or with --all, it opens on every subscribed project. A checkout that is not subscribed still has its own page.

The sample you can open without installing is the dashboard in this site. Those jobs are made up.

Subscribe

Install the factory in each project, then subscribe that checkout. The list lives in ~/.mfactory/fleet.toml.

cd /path/to/project-a && mfactory fleet subscribe
cd /path/to/project-b && mfactory fleet subscribe
mfactory fleet list
mfactory fleet queue
mfactory fleet dashboard
mfactory fleet unsubscribe

subscribe and unsubscribe take a path when you are not standing in the repository. mfactory status outside a repository shows every subscribed project. mfactory upgrade --all upgrades each one. A project that fails does not stop the others, and each repository still needs its own commit.

A fleet.toml in the current directory or a parent still wins, and so does FACTORY_FLEET. mfactory fleet init writes that local file. fleet add accepts a checkout only after the factory is installed there. fleet remove drops a project by its path or folder name.

Each job stays in its own checkout. Open that project and run /mfactory run, or /mfactory run 12 for one issue. The fleet does not merge pipelines or move a job between repositories. Two clones of one GitHub repository both appear if you add both paths. They do not share job files.

One board

mfactory dashboard and mfactory fleet dashboard open the same page. Choose All for one board, one pipeline per project, one job list, and one config table per project. Choose one project for that project's views. Queue rows that are not jobs yet stay on the board.

fleet queue runs each project's own .factory/bin/mfactory queue. A project that fails is reported, and the others still print.

Concurrency

Each project caps its own jobs with [run].concurrency (default 3). A job waiting for a person, or being validated after merge, does not count.

The fleet has a second cap, [fleet].concurrency in this factory's defaults.toml (also 3): that many new and resume rows across every project. concurrency in fleet.toml, or mfactory fleet queue --concurrency N, overrides the fleet cap. A project's factory.toml cannot set the fleet cap.

Later rows print as hold. Projects earlier in the file get the slots. wait, skip, and hold do not take a slot.
