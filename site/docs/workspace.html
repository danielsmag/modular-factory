Workspace and dashboard

The dashboard is a read-only page on your machine. The workspace is the list of checkouts that share that page and a second cap on how many jobs start.

Dashboard

mfactory start dashboard
mfactory stop
mfactory dashboard
mfactory dashboard --port 4747 --no-open

start dashboard serves the page in the background and returns. stop ends that process. dashboard serves the same page in the foreground until Ctrl C. The default port is 4747.

The page comes with the global install (install.sh --global), so a machine has one dashboard and no copy sits in .factory/. .factory/bin/mfactory dashboard, start and stop hand off to the global mfactory.

The page has five views:

  • Board. Three blocks that each fold. Jira: the Jira boards you choose, one or several, with their columns and cards; a picker lists every board the account can see. GitHub issues: each repository's open issues, newest first, with All, Assigned to me and Not in the factory. Factory: jobs by step, with a Now panel of the agents still on the current step.
  • Pipeline. A column of steps. Forward edges on the right, back edges on the left, and how many jobs sit in each step.
  • Jobs. What each job wrote: spec, build, checks, reviews.
  • Overview. Running slots, a running total of merged jobs with a steady-pace line, cost or time by step, and the job table. With a few merges a week, a per-day chart is mostly zeros.
  • Config. The merged configuration, and which file set each value.

It changes nothing. Approvals and feedback go through /mfactory or an issue comment. It answers only on 127.0.0.1, refuses another Host, and serves only .md and .log files from the jobs folder. See why.

Inside a checkout in the workspace, the page opens with that project selected. Outside a repository it opens on every project. A checkout that is not listed still has its own page.

Each project's own factory writes its job files. When those files come from an older factory, the page says to run mfactory upgrade in that project and still shows its jobs. When they come from a newer factory than the global one, the page says to run mfactory upgrade --self and hides that project's jobs until then.

The sample you can open without installing is the dashboard in this site. Those jobs are made up.

Planner

The planner reads the queue across every project in the workspace. It reports what one job cannot see: duplicates, an issue that must wait for another, two issues that touch the same files, a low-priority job ahead of a critical one. It only suggests. Nothing in a tracker or a job changes until you approve a finding.

/mfactory plan summary
/mfactory plan

plan summary scans when tickets changed, then reports with Needs attention first. In /mfactory plan you can ask about a finding. The orchestrator runs plan approve, plan dismiss, or plan release only when you say so, and shows what it will do first. Between queue passes, /mfactory run runs a due scan without holding up a job. The same verbs work in a terminal: mfactory plan summary, plan show, plan approve F-3.

The dashboard badge counts open findings at or above [planner] alert_at. The Planner view (#/planner) lists each finding and the action it proposes. Browser notifications are opt-in. Settings are in Configuration.

Add a project

mfactory install adds the checkout it installs into. The list lives in ~/.mfactory/workspace.toml. To add a project that was installed earlier, run this inside it:

cd /path/to/project-a && mfactory workspace add
mfactory workspace list
mfactory workspace queue
mfactory workspace remove

add and remove take a path when you are not standing in the repository. remove also takes the project's folder name. mfactory status outside a repository shows every project in the workspace. mfactory upgrade upgrades the global CLI and each of those projects. A project that fails does not stop the others, and each repository still needs its own commit.

A workspace.toml in the current directory or a parent still wins, and so does FACTORY_WORKSPACE. mfactory workspace init writes that local file. workspace add accepts a checkout only after the factory is installed there. An older ~/.mfactory/fleet.toml is renamed to workspace.toml the first time it is read.

Each job stays in its own checkout. Open that project and run /mfactory run, or /mfactory run 12 for one issue. The workspace does not merge pipelines or move a job between repositories. Two clones of one GitHub repository both appear if you add both paths. They do not share job files.

One board

Choose All for one board, one pipeline per project, one job list, and one config table per project. Choose one project for that project's views. Queue rows that are not jobs yet stay on the board.

With All, the Jira and GitHub blocks show each project under its name. The boards you choose, the GitHub filter, and the blocks you fold are kept in this browser, so the dashboard itself writes nothing. A card or an issue that is a factory job carries the job's chip and opens its drawer. The Jira block reads Jira's REST API with each project's own [tracker.jira] settings and the same account email and token the factory uses: the email from [tracker.jira].email or JIRA_EMAIL, the token from token_file, JIRA_API_TOKEN or the project's .env. If they come from the environment, start the dashboard from a shell that has them. A board the account cannot see shows its error in its own place, and the rest of the page still loads.

workspace queue runs each project's own .factory/bin/mfactory queue. A project that fails is reported, and the others still print. Queue cards link to the issue and open a drawer with the issue's body and comments, fetched when it opens.

Concurrency

Each project caps its own jobs with [run].concurrency (default 3). A job waiting for a person, or being validated after merge, does not count.

The workspace has a second cap, [workspace].concurrency in this factory's defaults.toml (also 3): that many new and resume rows across every project. concurrency in workspace.toml, or mfactory workspace queue --concurrency N, overrides that cap. A project's factory.toml cannot set it.

Later rows print as hold. Projects earlier in the file get the slots. wait, skip, and hold do not take a slot.
